# Telegram Business personal assistant

A bot that connects to **your own Telegram account** through Telegram Business
(*Chatbots*) and drafts replies to people who write to you, in your name and in
your style. Everything it knows about you comes from [`profile.md`](profile.md).

Replies are generated by the **Claude Code CLI** (`claude -p`) installed next to
the bot, signed in with your **Claude subscription** token from
`claude setup-token`. An Anthropic API key is never used.

Production runs on **Railway** (built from the `Dockerfile`, redeployed on every
push to GitHub). Your Mac is only for development and testing.

## What it does

- **PREVIEW mode is the default** (`AUTO_SEND=false`): replies are only written
  to the logs (`PREVIEW, not sent`) and to `data/previews.jsonl`. Nothing is sent.
- With `AUTO_SEND=true` replies are sent from your account automatically.
- **Which chats the bot sees is decided by Telegram only**:
  *Settings → Telegram Business → Chatbots* → the chats you pick there. The code
  has no allowlist.

### Behaviour

| Situation | What happens |
|---|---|
| Business connection of another account | Ignored, warning in the log |
| Which chats | Whatever you selected in *Business → Chatbots* |
| You write in a chat yourself | Saved to history, never answered; the bot stays quiet in that chat for `OWNER_TAKEOVER_MINUTES` (15) |
| Messages from bots (including the bot's own replies) | Ignored |
| Same message delivered twice | Handled once (remembered across restarts) |
| Service messages (title changes, pins, …) | Ignored; stickers, voice, photos become short tags like `[voice message]` |
| `/pause` | No replies until `/resume` (survives restarts) |
| Claude subscription usage limit | No retries until the reset time (or `LIMIT_COOLDOWN_MINUTES`), survives restarts; the owner is told in AUTO-SEND mode |
| Timeout / login error | Logged, nothing sent to the chat; the owner is told at most once per 10 minutes (AUTO-SEND) |
| Claude answers `[SKIP]` | Nothing shown or sent |
| Before every auto-send | Re-checks pause/limit/your own activity and asks Telegram again whether the connection is yours, enabled and allowed to reply |

### Commands (only from the owner, in a private chat with the bot)

- `/start` – instructions in Uzbek (mode, state, how to connect, commands).
  Anyone else gets a short Uzbek note that this is a private assistant; Claude
  is not called and nothing about you is revealed.
- `/pause`, `/resume`, `/status`.

Other direct messages to the bot are silently ignored.

## How Claude is called

One `claude -p` process per reply, started with `asyncio.create_subprocess_exec`
(never a shell):

```
claude -p --safe-mode --settings '{"disableAllHooks":true,"enabledPlugins":{...:false}}'
       --tools "" --strict-mcp-config --setting-sources "" --disable-slash-commands
       --no-session-persistence --system-prompt-file <temp file>
       --output-format json --effort low [--model ...]
```

- No tools, no MCP servers, no plugins (every built-in plugin is switched off),
  no skills, no hooks, no CLAUDE.md, no auto-memory, no saved sessions.
- `--bare` is **not** used: it ignores OAuth logins, so the subscription would
  stop working.
- The conversation goes through **stdin only**; the system prompt (with your
  profile) is a 0600 temp file in `data/claude-run`, deleted afterwards, so it
  never shows up in `ps`. Each run gets its own empty 0700 working directory.
- The child environment drops every `ANTHROPIC_*` variable, the Telegram token,
  Bedrock/Vertex/Foundry switches and `CLAUDE_CODE_SIMPLE`; it gets
  `CLAUDE_CODE_OAUTH_TOKEN` only if you configured one.
- The token is replaced with `[REDACTED]` in any CLI output before parsing.
  A rejected token gives a message with `CLI said: ...` so you can see why.
- `python bot.py --check-claude` proves all of this with a tiny request.

## Deploy to Railway

1. On a computer with a browser run `claude setup-token`, approve with your
   subscription account, copy the `sk-ant-oat...` token (valid 1 year).
2. In @BotFather: `/newbot`, then *Bot Settings → Business Mode* → turn on.
   Get your numeric id from @userinfobot.
3. Create a **private** GitHub repository and push this code
   (`profile.md` is baked into the Docker image).
4. Railway → *New Project* → *GitHub Repository* → pick the repo.
5. Service → *Variables* → *Raw Editor*:
   ```
   TELEGRAM_BOT_TOKEN=...
   OWNER_ID=...
   CLAUDE_CODE_OAUTH_TOKEN=sk-ant-oat...
   AUTO_SEND=false
   ```
   Optional: `CLAUDE_MODEL`, `CLAUDE_EFFORT`, `CLAUDE_TIMEOUT_SECONDS`,
   `LIMIT_COOLDOWN_MINUTES`, `OWNER_TAKEOVER_MINUTES`, `HISTORY_LIMIT`.
   Not needed: `CLAUDE_BIN`, `DATA_DIR`, `PROFILE_PATH`.
6. Volume: right-click the canvas (or Cmd+K) → *Volume* → choose the service →
   mount path exactly **`/app/data`** → *Deploy*. Without a volume, history,
   pause and limit state are lost on every deploy.
7. Logs should show `Bot @... is running`, `Mode: PREVIEW` and
   `Claude auth: subscription token from environment variables`.
   Red lines in Railway just mean stderr, not errors.
8. Send `/start` to the bot. Then Telegram *Settings → Telegram Business →
   Chatbots* (needs Telegram Premium): enter the bot username, choose the chats,
   allow replying. The log shows `Business connection ...: user=<id> enabled=True`.
9. When someone writes to you, a `PREVIEW, not sent` block appears in the log.
   Happy with the drafts? Set `AUTO_SEND=true`.

Notes:

- Run the bot in **one place only**: two pollers with the same bot token fight
  each other (do not run `python bot.py` locally while Railway is running).
- Every push redeploys. Changing `profile.md` also means commit + push.
- Token expired or leaked: run `claude setup-token` again and update the
  Railway variable. Bot token leaked: `/revoke` in @BotFather.

## Local development

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env && chmod 600 .env   # then edit .env with a text editor
.venv/bin/python bot.py --check-claude
.venv/bin/python bot.py --try "Salom, bugun bo'shmisan?"
.venv/bin/python bot.py
```

If `CLAUDE_CODE_OAUTH_TOKEN` is empty, the machine's own `claude` login is used.

### Commands and exit codes

| Command | Purpose | Exit code |
|---|---|---|
| `python bot.py` | Run the bot with `.env` | 2 on config error or rejected bot token |
| `python bot.py --settings-from-env` | Container mode (Railway); settings variables are removed from the process environment after reading | same |
| `python bot.py --check-claude` | Check the CLI: init event present, tools/MCP/plugins/skills empty, no API key, first-party provider | 0 ok, 1 failed, 2 config |
| `python bot.py --try "text"` | Draft a reply to a made-up message, no Telegram | 0 ok, 1 Claude error, 2 config |

`--check-claude` and `--try` do not need Telegram settings and work with
`--settings-from-env` too.

### Tests

```bash
.venv/bin/python -m pytest
```

All tests are offline: a recording fake Telegram session and a fake `claude`
executable.
